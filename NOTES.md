## Stage 0a: Data spike

ADAPTER=robinhood, headless auth confirmed, token lifetime: access token expires_in observed at ~746823s and ~821409s (~8.6-9.5 days) across two runs; refresh_token is issued (has_refresh_token=True), so unattended renewal without a browser is possible once a refresh token is persisted.

Method: ran `spike_mcp_oauth_test.py` (official `mcp` Python SDK, `streamable_http_client` + `OAuthClientProvider`) as a plain script against `https://agent.robinhood.com/mcp/trading`, independent of any Claude Code/Desktop session. The OAuth authorization-code + PKCE flow completed via a localhost callback server and the default browser, `session.list_tools()` returned 73 tools, and `get_equity_quotes(["AAPL"])` returned live data.

Important safety implication for Stage 2 (src/gateway/):
- The OAuth token's scope is `internal`, not read-only. The 73 tools returned include every order-placing, reviewing, cancelling, and exercising function (`place_option_order`, `place_equity_order`, `cancel_option_order`, `exercise_option`, `review_option_order`, etc.). Robinhood does not offer a narrower read-only scope for this MCP server.
- This means the capability boundary (PRD section 7 / CLAUDE.md rule 3) has zero support from the credential itself. It must be enforced entirely by DataGateway's code: the adapter module must never expose a generic `call_tool(name, args)`, and DataGateway's ALLOWLIST must be the only path the agent ever touches. Rule 2 (no order-placing function ever written/imported/stubbed) is the only thing standing between this credential and a real trade.
- Token persistence design needed in Stage 2: the spike used in-memory-only token storage (nothing written to disk). The real adapter needs a durable token store (refresh_token + access_token) written only inside src/gateway/adapters/robinhood.py, loaded from an env var pointing at a file path or secret, never logged, never passed to src/agent/. This still needs to be designed - flagging as a Stage 2 task, not deciding the mechanism now.
- One-time interactive consent was required to mint the refresh token (a browser had to complete the OAuth redirect once). That happened on Jayden's desktop machine with an already-authenticated Robinhood browser session, so no manual click-through was visibly needed this run - but a fresh machine (e.g., a VPS in the Phase 2 deploy) would need a one-time interactive re-auth before it can run headlessly. This matches Robinhood's own documentation ("you can only open an agentic account and authenticate your agent on a desktop device").

Spike artifact: `spike_mcp_oauth_test.py` at repo root, kept for reference. Not part of the src/ layout; not imported by anything in Stage 2.

## Stage 1: Schema and models

- `watchlist_symbols.ticker` is the primary key (not a surrogate `id`) - it's inherently unique and every other table's `ticker` FK references it directly, avoiding a pointless join.
- `paper_positions.decision_id` (FK to `decisions.id`) was added even though the Stage 1 prompt's column list for `paper_positions` doesn't name it. Without it there'd be no way to trace a position back to the action/thesis that opened it, which Stage 6's evaluator needs (`direction_correct` compares the underlying's move against the thesis's direction). Same reasoning for `decisions.ticker` (needed to know which underlying a decision concerns) and `snapshots.ticker`/`run_id` (needed to know whose snapshot it is).
- `decisions` bundles `thesis`, `evidence_for`, `evidence_against`, and `invalidation` from PRD section 6's TradeCandidate into one JSONB column named `reasoning`, rather than four separate columns - the prompt says "thesis and evidence fields as JSONB" (singular blob), and it mirrors the TradeCandidate schema directly. Null for Cohort A/B, which don't produce a thesis.
- `confidence` is a plain `Float`, not `Decimal`/`Numeric` - CLAUDE.md's "money is Decimal" convention applies to money, and confidence (0.0-1.0) isn't money.
- Real bug caught and fixed: Alembic's autogenerate does not emit `DROP TYPE` for Postgres enum columns (they can be shared across tables, e.g. `cohort` is used by both `decisions` and `paper_positions`), so the generated `downgrade()` only dropped tables. `alembic upgrade head` -> `downgrade base` -> `upgrade head` failed with `DuplicateObject: type "run_status" already exists` on the second upgrade. Fixed by adding explicit `sa.Enum(name=...).drop(op.get_bind(), checkfirst=True)` calls for all 8 enum types at the end of `downgrade()`, after every table that references them is gone. Verified the full cycle succeeds after the fix.
- `alembic/versions/` is excluded from ruff in `pyproject.toml` - autogenerated migration files use their own formatting (unsorted imports, `Union` instead of `|`, long lines) that isn't worth hand-fixing on every future migration.
- Integration test (`tests/integration/test_migrations.py`) wraps its inserts in a transaction that's rolled back in `conftest.py`'s `db_session` fixture teardown, so re-running it locally never hits a duplicate-key conflict and leaves no residue - verified by querying `watchlist_symbols` after a test run and finding it empty.
- `tests/integration/conftest.py`'s `migrated_engine` fixture skips (not fails) when Postgres isn't reachable at `DATABASE_URL`, so `pytest` still works on a machine with Docker down; it ran for real here against the Stage 0b docker-compose Postgres on `localhost:5432`.

## Stage 2: DataGateway and adapter

Layout: `src/gateway/allowlist.py` (ALLOWLIST + CapabilityError), `adapter.py` (the five-method Protocol), `types.py` (Quote/OptionContract/Bar/Headline, Decimal money), `gateway.py` (DataGateway), `factory.py` (adapter selection), and `adapters/`: `mcp_client.py` (one MCP session on a background event loop, sync `call()`), `oauth_browser.py` (one-time browser consent), `robinhood.py` (tool-response mapping), `robinhood_auth.py` (`make robinhood-auth`), `fake.py` (deterministic synthetic data).

- Two allowlists, on purpose. `ALLOWLIST` in `allowlist.py` is the agent-facing one (five names). `READ_TOOLS` in `mcp_client.py` is a second, inner one: the MCP session could technically name any of the 73 tools the Robinhood server advertises (Stage 0a showed the token is full-scope), so `McpReadClient.call()` raises CapabilityError for anything outside its seven `get_*` tool names before any network I/O. The deny-list words from PRD section 7 appear nowhere in `src/`, only in `tests/test_capability_boundary.py`.
- `DataGateway.__getattr__` raises CapabilityError for any unknown non-dunder name. CapabilityError subclasses AttributeError so `hasattr()`/`copy` don't explode, and `__slots__` keeps the instance from growing attributes. `tools()` returns the five bound functions in ALLOWLIST order; each carries `is_mutating = False` via `read_only`.
- `src/agent/tools.py` (`agent_tool_list(gateway) -> gateway.tools()`) was added now, not in Stage 4, so boundary assertion 1 tests the agent's actual tool list rather than the gateway's. Stage 4 must build on it, not replace it.
- Boundary assertion 4 checks the worker's *declared* environment (docker-compose `worker.environment` keys, its `env_file`, and `.env.example`) always, and the live `os.environ` only when `SERVICE_ROLE=worker` - this dev machine carries `CLAUDE_CODE_EXECPATH`, which would otherwise be a false positive. `SERVICE_ROLE` was added to the compose api/worker services for that reason.
- Token persistence: `FileTokenStorage` writes the OAuth token + registered client info as JSON at `ROBINHOOD_TOKEN_PATH` (default `data/robinhood_token.json`; `data/` is gitignored; compose mounts `./data:/data` into the worker). `make robinhood-auth` does the one-time browser consent on a desktop. Headless callers with no token get `AuthRequired` with that instruction instead of a hang. The token value is never logged or returned.
- `.env` now holds host-side values (`DATABASE_URL` on localhost, token path under `data/`); docker-compose overrides the container-specific ones. No more `DATABASE_URL=...` prefixes on local commands.
- Robinhood mapping: quote = `get_equity_quotes` (last_trade_price, bid/ask, adjusted_previous_close); chain = `get_option_chains` (filter `symbol == ticker`, `can_open_position`) -> `get_option_instruments` per chain with all in-window expirations in one call, following `next` cursors, keeping `state=active` + `tradability=tradable` only -> `get_option_quotes` in batches of 40 (above 20 the server drops its "closes" block, which we don't use); historicals = `get_equity_historicals` daily bars, skipping `interpolated`, last N; earnings = `get_earnings_results` (per-ticker, not the market-wide calendar), first report with `eps.actual == null` and date >= today; news = `get_equity_news`. Contract IDs are Robinhood instrument UUIDs.
- Snapshot job stores every active contract in the DTE window with `eligible=False`, `ineligible_reason="pending_eligibility"`; Stage 3's filter flips them. One transaction per ticker; run status is COMPLETED if any ticker stored and FAILED only if none did (a partial day is still a day). First real run (run 11): AAPL 726, MSFT 808, NVDA 792, AMZN 536, GOOGL 990 contracts, 3,852 total, 61s, ~160 MCP calls. Phase 2 candidate: prune strikes far from spot to cut rows (~4k/day now).
- FakeAdapter prices contracts with a rough Black-Scholes-shaped time value (decaying with moneyness) over a strike ladder of about +/-20% of spot, so every ticker gets a mix of contracts passing and failing each PRD section 4 rule (first version priced everything above the $300 premium cap; caught by `test_fake_chain_mixes_eligible_and_ineligible`). Added `"fake"` to `AdapterName` for tests, dry runs, and Stage 7's integration test.
- yfinance adapter not built - PRD asks for one live adapter and Robinhood works headlessly. `factory.build_adapter("yfinance")` raises NotImplementedError; the name stays in `AdapterName` for Phase 3.
- Robinhood returns 400 to the MCP SDK's session-DELETE on close; harmless, silenced with `terminate_on_close=False`. `httpx2`/`mcp` loggers are set to WARNING in the snapshot CLI.
- Run ids in the local DB have gaps (integration tests create runs inside rolled-back transactions; Postgres sequences don't roll back). Cosmetic.

## Stage 3: Eligibility filter, validator, and Cohort B screener

- `src/agent/schema.py` (TradeCandidate) was created now, not in Stage 4, because `src/validator/candidate.py` needs it to exist first. Stage 4 builds bundle.py/prompt.py/runner.py around this schema, not a new one.
- Split validation responsibility: Pydantic (`schema.py`) enforces only self-contained field constraints (types, confidence range, evidence list length 2-4, contract_id required iff a trade is being made) - nothing that needs a database or the watchlist. `candidate.py` enforces everything that needs run-time context (ticker on watchlist, contract eligible for that ticker, action matches contract type, max_loss vs. MAX_PREMIUM). This matches Stage 3's own prompt, which lists "ticker is off-watchlist" as a separate rejection reason from "schema is invalid" - i.e. watchlist membership was never meant to be schema-level.
- `TradeCandidate.action` is typed as `src.models.enums.Action` (the same StrEnum the `decisions` table's column uses), not a bare `Literal[...]`. Same JSON contract either way (StrEnum serializes as its string value), but it means Cohort B's `ScreenerDecision.action` and Cohort C's `TradeCandidate.action` are directly comparable without a translation layer at Stage 7.
- Eligibility checks run in the PRD's literal order (DTE, spread%, OI, premium) and return the first failing reason. Zero-bid contracts need no special case: `(ask-bid)/mid` already comes out huge when bid=0, and `mid<=0` (both quotes zero) is treated as `spread_too_wide` directly.
- Verified against real Stage 2 data (run 11, live Robinhood pull, 3852 contracts): a real, readable mix of eligible/ineligible rows with reasons - e.g. MSFT: 4 eligible, 350 open_interest_too_low, 46 premium_too_high, 408 spread_too_wide.
- Screener thresholds (bullish: 20-day return > +2% AND RSI > 55; bearish: return < -2% AND RSI < 45) are a build-time choice documented in `screener.py`'s docstring, not from the PRD - PRD explicitly says the exact rule matters less than that it's deterministic and documented. Contract selection: minimize `|dte-30|` first, break ties by `|strike-spot|`.
- RSI uses a simple 14-period average of gains/losses (not Wilder's exponential smoothing) - deterministic and hand-verifiable in tests; PRD doesn't specify a smoothing method.
- Real bug found and fixed: `tests/integration/conftest.py`'s Postgres reachability check had no connect timeout, so a stopped/unreachable Postgres made the *entire test suite* hang for minutes instead of skipping cleanly (discovered when Docker Desktop had stopped between sessions and `pytest` just hung). Fixed with `connect_args={"connect_timeout": 3}`. Also added `pytest-timeout` (60s default, `[tool.pytest.ini_options] timeout = 60`) as a permanent safety net so any future hang fails loudly instead of silently stalling CI.
- A separate real bug caught by the test suite itself: `rsi_14`'s pairwise `zip(window, window[1:], strict=True)` can never work - the two arguments are deliberately different lengths (15 closes -> 14 changes) - `strict=True` asserts equal length. Fixed to `strict=False`.

- Watchlist tickers: AAPL, MSFT, NVDA, AMZN, GOOGL - liquid large caps with active weekly/monthly options chains, per PRD section 4's "liquid large caps only." No PRD-specified list, so picked for options liquidity (tight spreads, high OI at many strikes).
- DB driver: `psycopg[binary]` (psycopg3), not psycopg2 or asyncpg - modern, actively maintained, works with SQLAlchemy 2.x sync engine which is simpler to reason about for a once-a-day batch job than an async engine.
- Package layout: `src/` is a regular package (has `__init__.py`) importable as `src.gateway`, `src.agent`, etc., with the repo root on `pythonpath` via pyproject's `[tool.pytest.ini_options]` and mypy's `mypy_path = "."`. No separate install step needed for tests/mypy to resolve imports; `make install` still does an editable install for running the app for real.
- `src/logging/` does not shadow the stdlib `logging` module because Python 3 absolute imports mean `import logging` always resolves to stdlib; only `from src.logging import ...` reaches this package.
- Frontend placeholder: added `frontend/index.html` as a static placeholder page (referenced by docker-compose's frontend service) so "frontend can be a placeholder static page" (Stage 0b done-when) is satisfiable once Jayden's Dockerfile serves it. Real dashboard replaces this in Stage 8.
- docker-compose port mapping: api 8000:8000 (uvicorn default), frontend 3000:80 (assumes a static/nginx-style Dockerfile serving on container port 80), postgres 5432:5432 (exposed to host for local `psql`/debugging use in Stage 1-2), worker has no exposed ports (internal scheduler process only).
- CI installs and runs via `make check`/`make install` directly - GitHub's `ubuntu-latest` runners ship `make` natively, so this doesn't depend on Jayden's local Windows `make` install.
